# 交互表面合同（Interaction Surface Contract）

> Gate B / C 的桥梁。页面合同不能只列“有展示、有编辑、有空态”，还必须说明用户从默认浏览态怎样进入任务、在哪完成、怎样退出，以及返回后保留什么。

## 1. 为什么需要这一层

常见失败不是缺字段，而是把所有状态同时铺在页面上：

- 选择器、编辑器、关系预览和异常说明永久占据默认页；
- “添加 / 编辑”按钮只改一行提示，没有打开真正的任务层；
- 为了评审弹窗状态，弹窗默认遮住产品，导致默认体验不真实；
- 页面有多个表单，但无法说明哪个动作进入哪个表单；
- 取消、Escape、未保存恢复和焦点返回没有定义。

这些问题属于产品行为与页面合同，不是 CSS 收尾。

## 2. 先分五种模式

每个 Route-level 页面先声明默认模式，再登记可进入的其他模式：

| 模式 | 用户心智 | 页面职责 |
|---|---|---|
| Browse | 我有哪些对象、哪项需要处理 | 列表、分组、筛选、状态、唯一主 CTA |
| View | 我正在看哪一个对象、当前事实是什么 | 只读详情、来源、影响、上下文动作 |
| Create | 我要产生一个新对象或新关系 | 收集创建所需的最小完整输入 |
| Edit | 我要修改已有草稿或显式派生副本 | 显示编辑对象身份、基准版本、未保存状态 |
| Confirm | 这次动作会带来什么结果 | 只确认不可逆、破坏性或会改变身份的动作 |

默认 Browse / View 不得因为“页面具备编辑能力”而常驻完整编辑器。编辑必须有明确触发器。

## 3. 表面选择矩阵

| 表面 | 适用 | 不适用 | 最低行为合同 |
|---|---|---|---|
| Inline | 1～2 个简单字段、低风险、立刻可逆，且不打断浏览 | 多区块表单、创建新身份、需要比较来源 | 明确进入/退出编辑态；Enter/Escape；保存失败保留值 |
| Popover | 小量选择或解释，内容短且不滚动 | 长表单、关键决策、移动端主要流程 | 锚点、外点关闭、Escape、焦点返回 |
| Modal | 短期聚焦任务或确认，字段很少 | 两步以上创建器、复杂表格、需要持续看背景 | 标题说明任务；主/次动作；焦点圈；关闭规则 |
| Context drawer | 1～2 步中等复杂编辑，需要继续参考父页 | 需要宽表格或三步以上深流程 | 触发对象语境；滚动体；未保存关闭提示；返回原行 |
| Wide overlay | 两步以上创建、交互选择、关系图或变体矩阵 | 一个开关或简短确认 | 步骤/分区导航；固定提交区；草稿恢复；移动端转全屏 |
| Full page | 高复杂度、可深链、多人协作、长时间任务 | 轻量上下文修改 | 面包屑/返回；对象身份；保存状态；离开保护 |

选择表面依据任务复杂度和上下文需求，不依据“这样看起来更丰富”。

## 4. 每项动作的强制登记表

| Action ID | 起点模式 | 触发器 | 目标模式 | 承载表面 | Commit | Cancel / Close | Unsaved / Recovery | 返回焦点 / 语境 |
|---|---|---|---|---|---|---|---|---|
| A-01 | Browse | `＋ 添加一条关联` | Create | Wide overlay | 创建关联 | 取消 / Escape | 本地草稿可恢复；有修改时确认离开 | 回到新增按钮；高亮新关系 |

硬规则：

1. 每个 CTA 必须有 Action ID；只更新 demo 文案不算行为完成。
2. 创建与“把已有对象加入当前容器”不是同一动作；前者产生新身份，后者产生关系。
3. 编辑已批准对象前必须先定义：原地新版本、课程内派生、还是禁止编辑。
4. 提交后必须说明生成或改变了哪个对象；“保存成功”不能掩盖身份变化。
5. 关闭层后恢复原触发器焦点；键盘焦点不得落回页面开头。
6. 异步提交失败时保留全部输入，并把错误放在失败字段或任务层顶部。

## 5. 真实预览合同

预览不是编辑页手写的相似卡片。每个预览必须登记：

| 项 | 必答 |
|---|---|
| Preview source | 精确草稿 revision / 已批准版本 / release perspective |
| Renderer | 是否与真实消费端共用 renderer / component contract |
| Fixture | 使用哪份虚构数据；禁止真实用户数据 |
| Controls | 哪些属于内容，哪些属于全局运行控件 |
| Variant | 年龄、声学、渠道如何切换；切换后解析哪一份内容 |
| Stale | 来源改变后如何标记过期并重建 |

不变量：同一 preview build 与真实运行端消费同一 resolved manifest；教师说明、调试标签和产品注释不得渲染进孩子画面。

### 5.1 反馈投影合同

交互完成后不要直接问“用哪个 toast / 气泡”，先登记语义所有者：

| 反馈 | Owner | Commit | 表面 |
|---|---|---:|---|
| 用户原话 | 用户 | 是 | 用户气泡 / 原话记录 |
| 用户已完成选择或点击 | 用户 | 是 | 动作回执 / 创作足迹 |
| AI / 角色回应 | AI / 角色 | 视流程 | AI 气泡 / 当前问句 |
| 系统处理结果 | 系统 | 状态变化 | 任务面 / 结果卡 / 状态层 |
| 重播、预览、放大、点错 | 本地交互 | 否 | 自动消失的 ActionEcho |
| 等待安慰 | 系统处理投影 | 否 | processing 期间的 thinking / 显影 |

同一事件可以派生多种投影，但不能把系统结果写成用户说过的话。完整方法见 [source-projection-and-runtime.md](source-projection-and-runtime.md)。

## 6. 产品态与评审态

- **产品态**：只有一个真实页面实例；导航、按钮、弹层和返回可操作；默认不展开隐藏任务。
- **评审态**：可在产品框外列 Default / Empty / Loading / Error / Interrupted / Permission 缩略证据，或用独立评审路由切换。
- 评审态不能复制出第二套可编辑表单，不能成为业务页面的默认内容。
- 静态 HTML 也要实现最小真实交互：打开、关闭、选择、提交反馈、焦点恢复和 URL / hash（适用时）。

## 7. Gate C 自检

- [ ] 默认模式和页面唯一任务明确。
- [ ] 每个添加、编辑、选择、预览、提交动作都有触发器和 Action ID。
- [ ] 表面选择符合复杂度，不把三步流程塞进小弹窗，也不把简单开关做成整页。
- [ ] 创建 / 加入 / 复制 / 派生四种身份变化没有混用。
- [ ] Cancel、Escape、未保存、失败、恢复与焦点返回已定义。
- [ ] 预览使用真实消费端 renderer / manifest；内容与全局运行控件分离。
- [ ] 用户动作、系统结果、AI 回应、短 Echo 与等待反馈各有正确 owner 和表面。
- [ ] 非 Commit 动作不进入持久历史；多 renderer 共用同一 Commit 与结果。
- [ ] 默认产品框没有为了评审而永久展开的弹窗、抽屉或状态画廊。
